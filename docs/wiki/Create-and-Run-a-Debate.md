# 创建和运行辩论

## 三种创建方式

### AI 自动规划

默认推荐。只需填写辩题，背景、领域和深度可选。AI 返回：

- 背景说明
- 正方立场
- 反方立场
- 核心争议点
- 研究方向
- 建议证据类型

结果可以编辑；只有确认创建后才会写入 Session。

### AI 辅助完善

适合已经有初步立场的用户。填写辩题和双方初始立场，AI 会补充完整立场、潜在漏洞与研究重点。

### 完全手动

不调用规划模型。你自己填写背景、双方立场和运行配置。

## 角色绑定

创建前至少需要：

- 正方
- 反方
- 主持人

裁判可选。缺少独立裁判时应用会给出警告，但不一定阻止启动。每个角色只引用 ModelProfile，不保存或复制 API Key。

## 启动前检查

DebateSetupValidator 会检查：

- 必需角色是否存在；
- ModelProfile 和 ProviderConnection 是否存在；
- 连接是否启用；
- Base URL、协议、credentialRef 与 Model ID 是否有效；
- 模型能力是否满足当前任务；
- 当前协议是否有可用 Adapter。

错误会阻止启动，警告只提醒风险。Renderer 不会自行复制一套校验规则。

## 运行控制

- **启动**：从当前可运行阶段开始。
- **暂停**：取消当前在途请求，保存部分文本，并停止继续推进。
- **继续**：从暂停位置重新开始。
- **停止**：结束整个 Session，之后不再调用模型。
- **跳过当前阶段**：在某个环节耗时过长或无法完成时直接进入下一阶段。
- **重试失败轮次**：创建一个带 `retryOfTurnId` 的新 Turn，不覆盖失败记录。

## 阶段进度

默认流程包括主持、公共资源、双方规划与研究、论证草拟、开篇、反驳、自由辩论、总结、裁判和完成。界面使用分段进度条显示当前位置。

研究过程默认折叠。正式辩论发言是页面重点，刷新页面后会从 SQLite 恢复，而不是只依赖内存。

## 遇到长时间等待

页面会显示当前角色、正在执行的动作、已等待时间、流式正文或思考活动。你始终可以停止或跳过当前阶段，不会被单个模型请求永久卡住。
